JeffreyApps

A single Rails app that combines the existing to-do list and bookmarking apps into one deployable product. It reuses the shared template's sidebar menu and account system, presenting To-Dos and Bookmarks as two feature areas under one login, so both projects ship as a single upload. The combined app lives in a brand-new folder; the original simple-todos and bookmarker projects stay untouched so they can still be updated independently.

Rails 8 Ruby 3.3.6 React 19 Inertia.js TypeScript Vite 7 PostgreSQL Tailwind CSS v4 Solid Queue Hatchbox Anthropic (Claude) Resend

What the app does

  • One account, both areas

    Sign up, log in, reset a password, manage a profile — a single login covers both To-Dos and Bookmarks.

  • Unified navigation & dashboard

    One collapsible sidebar links Home, To-Dos, and Bookmarks. The Home page shows a snapshot of each.

  • Keep a to-do list

    Add tasks, check them off, edit the text, and delete them. Unfinished items rise to the top.

  • Save bookmarks

    Store a URL with a title and notes. Website vs YouTube is detected automatically.

  • AI page summaries

    Each saved bookmark gets a short automatic summary of the page, regenerated on demand.

  • Tag & filter bookmarks

    Attach tags while typing, then rename, merge, or delete them, and filter the list by one tag.

  • Share a bookmark by email

    Send any bookmark to someone with an editable subject and message; they get its title, URL, and summary.

  • Admin area

    An admin-only user list and the live design-system reference page, restricted to admin accounts.

Already provided by the Build New starter

  • Signup / login / logout
  • Email password reset
  • User model
  • Authenticated app shell + collapsible sidebar
  • Profile page
  • Settings page
  • Dark-mode toggle
  • Admin user list
  • Design-system reference page
  • Background job queue (Solid Queue)
  • Dev email previews

Out of scope (v1)

  • Cross-linking to-dos and bookmarks — the two areas stay independent; no shared entity and no "convert this into a to-do" action.
  • Data migration from the old apps — the combined app starts with empty tables; existing to-dos and bookmarks are not imported.
  • Sharing to-dos by email — email sharing stays bookmark-only, exactly as it is today.
  • AI summaries for to-dos — summaries stay bookmark-only.
  • Tags on to-dos — tagging stays bookmark-only.
  • Teams / collaboration / shared lists — single-user; every account's data is private to that account.
  • Third-party login, billing, mobile app, browser extension — none are part of v1.
  • Full-text / advanced search across both areas — only the existing per-list tag filter on bookmarks.
  • Changes to the original repos — simple-todos and bookmarker are left exactly as-is and are not deprecated by this project.

External integrations

Anthropic (Claude)

AI summaries

Writes the short summary of each bookmarked page in the background. Same provider the bookmarker app uses today. Without the key, summaries fail gracefully to "Summary unavailable" — useful for local development.

Credentials needed

  • ANTHROPIC_API_KEY

Resend

Email

Delivers shared-bookmark emails and password-reset emails in staging and production. Same provider the bookmarker app uses today. Development previews mail in the browser and needs no key.

Credentials needed

  • RESEND_API_KEY

Fetching a page's text and metadata for the summary is done by the app directly — no third-party service or key.

Data model

What the app needs to remember. It is the union of the two apps' existing models — nothing new. Every entity also keeps created/updated timestamps automatically.

User

email The address the person signs in with.
password Their login secret (stored securely by the starter).
name The person's display name. Optional, up to 100 characters. (Added during the build to support a personalized greeting on the Home page.)

Related to · owns all Todos, Bookmarks, and Tags. Provided by the Build New starter.

Todo

description The task text. Required, up to 500 characters.
completed Whether it is checked off. Starts as no.

Related to · belongs to one User.

Bookmark

url The link being saved. Required; must be a valid http/https address.
title The headline of the page. Required, up to 500 characters; auto-filled from the page if left blank.
url type "website" or "youtube", detected automatically from the URL.
summary The AI-generated summary of the page. Optional; filled in by the background job.
summary status Where the summary stands: pending, completed, or failed.
notes The user's own free-text notes. Optional, up to 10,000 characters.

Related to · belongs to one User; can have many Tags.

Tag

name The label. Required, up to 50 characters, unique per user, case-insensitive.

Related to · belongs to one User; can be attached to many Bookmarks.

Bookmark–Tag link

— The connector that attaches one Tag to one Bookmark. No fields of its own; each pairing is unique.

Related to · joins one Bookmark and one Tag.

Milestones

1

Shell & navigation

Stand up the combined app on the Build New template with JeffreyApps branding and a single navigation shell that both feature areas will hang off.

What gets built

  • New Rails app from the Build New template in the jeffreyapps folder
  • "JeffreyApps" brand name in the sidebar and browser tab
  • Collapsible left sidebar with Home, To-Dos, and Bookmarks; user menu (Profile, Settings, theme toggle, Admin, Sign out) at the bottom
  • Sidebar collapse state remembered between visits; mobile hamburger + slide-over
  • Placeholder To-Dos and Bookmarks pages and a Home/dashboard route, all reachable when logged in
  • Active nav item highlights based on the current page

Not in this milestone

  • Any real to-do or bookmark functionality
  • Dashboard snapshot content
  • Tags, AI summaries, email sharing
  • Deployment

Done when: You can sign up, log in, and click between Home, To-Dos, and Bookmarks in the sidebar — each showing a titled placeholder page — on both desktop and mobile, with the sidebar collapsing and remembering its state.

2

To-Dos

Bring the to-do list from simple-todos into the combined app as a fully working To-Dos area.

What gets built

  • A To-Dos page listing all of the signed-in user's to-dos
  • Add a to-do from a text box
  • Check / uncheck a to-do to mark it complete
  • Edit a to-do's text; delete a to-do
  • Incomplete items sort above completed ones, then oldest first
  • Empty state when there are no to-dos

Not in this milestone

  • Due dates, priorities, reminders, sub-tasks, lists/folders
  • Tags on to-dos
  • Drag-to-reorder, recurring to-dos
  • The dashboard to-do snapshot (milestone 5)

Done when: A logged-in user can add, edit, complete, uncheck, and delete to-dos on the To-Dos page, and incomplete items always appear above completed ones.

3

Bookmarks & Tags

Bring bookmarks and tagging from bookmarker into the combined app, minus the AI and email pieces.

What gets built

  • A Bookmarks page listing saved bookmarks, newest first
  • Add a bookmark: URL plus optional title (auto-filled from the page if blank) and optional notes
  • Website vs YouTube type detected from the URL and shown
  • A bookmark detail view; edit title, notes, and tags; delete a bookmark
  • Add tags by typing, with existing tags suggested and new ones created on the fly
  • A Tags page listing all tags, with rename, merge-into-another-tag, and delete
  • Filter the bookmark list to a single tag; empty states for both pages

Not in this milestone

  • AI summaries (the summary area can show a neutral placeholder for now)
  • Email sharing
  • Bulk import/export, folders/collections, favorites, archive/trash
  • Full-text search, duplicate detection, preview thumbnails

Done when: A logged-in user can add, view, edit, tag, filter, and delete bookmarks, and can rename, merge, and delete tags from the Tags page.

4

Summaries & sharing

Layer the two external integrations — Anthropic summaries and Resend email — onto the bookmarks area.

What gets built

  • When a bookmark is saved, a short summary of the page is generated in the background
  • The bookmark shows a "pending" state, then the summary text once it is ready
  • A "Regenerate summary" action on the bookmark detail view
  • A failed summary shows "Summary unavailable" and can be retried; works for website and YouTube URLs
  • A "Share" button opens a small form: recipient email, plus an editable pre-filled subject and body
  • Sending delivers a readable email with the bookmark's title, URL, and summary (Resend in production; browser preview in development)

Not in this milestone

  • Hand-editing the stored summary, or choosing its length / style / language / model
  • Summary version history or scheduled re-summarizing
  • Share history, open/click tracking, multiple recipients, attachments, scheduled sends
  • Public share links; sharing or summarizing to-dos

Done when: Saving a bookmark produces an AI summary within a short wait, "Regenerate summary" replaces it, and the Share form sends an email containing the bookmark's title, URL, and summary.

5

Dashboard & deploy

Fill in the Home page with a combined snapshot of both areas, do a final polish pass, and ship the app to production.

What gets built

  • The Home page shows a greeting, an open-to-dos snapshot (count plus the next few items), and a recent-bookmarks snapshot (the few most recently saved)
  • Each snapshot links through to its full page
  • Final visual and copy polish across the app at desktop and mobile widths
  • The app is deployed to production on Hatchbox, with the two API keys configured, and verified at its live URL

Not in this milestone

  • Inline adding or editing from the dashboard (links only)
  • Charts, streaks, activity feeds, or a dashboard search box
  • Any new feature work in the To-Dos or Bookmarks areas

Done when: The live production URL loads the app, a logged-in user sees an accurate open-to-dos count and recent bookmarks on the Home page, and both snapshots link to their full pages.
